# 虚室生白

## 算力与功耗难题
在端侧部署大语言模型，传统的全量参数前向传播（Dense GEMM）在每一次生成新词时，都会迫使硬件执行极其庞大的全连接矩阵乘法。这不仅极大地消耗了算力，其庞大的计算量更会带来严重的设备发热与功耗崩塌问题。

为了打破这一瓶颈，本仓库的核心思路非常直接：**在推断生成时，动态切断大模型中海量无用的全连接（Fully Connected）计算**。
核心目标是：图让硬件在计算时具备“按需唤醒”的能力，物理跳过大部分闲置神经元的读取与点积计算，从而大幅降低单步生成的消耗，实现**虚室生白**。

## 当前阶段的工作与探索

### 1. 权重聚类与重排 (Weight Clustering)
要在海量的全连接层中精准地“切断无用连接”，物理底层的内存配合必不可少。
通过引入大量校准数据（Calibration Data），分析 MLP 全连接层中各个维度的协方差，将那些语义关联紧密、经常同时被激活的连接，强制物理重排到相邻的内存块（Block）中。这一工作使得大模型原本随机散漫的权重连接具备了“局部聚集性”，从而使得在后续切断大段大段的无用全连接区块时，能够真正转化为内存读取带宽上的加速。

### 2. 动态绝对稀疏 (Dynamic Absolute Sparsity)
为了判断哪些全连接是“无用的”，必须要有一套精准的甄别算法。

**被证伪的“时序增量（Delta）”算法：**
最初的设想是利用前后词的连续性，计算两步之间的特征差值（$\Delta X = X_t - X_{t-1}$），只唤醒那些特征发生明显变化的神经元（$\Delta Z$）。然而实测证明，自回归生成是一个闭环：在某一步切断连接所产生的一丁点误差，会在 $Z_t = Z_{t-1} + \Delta Z$ 的时序累加中发生致命的“滚雪球爆炸”，导致模型迅速吐出乱码。

**“动态绝对稀疏”算法：**
为此，本仓库彻底抛弃了时序依赖，转而实现了免训练的“绝对门控”机制：
算法不再参考上一个词，而是完全基于当前输入词的绝对状态 $X_t$。通过将全连接层原生的权重绝对值大小（$W_{norm}$）直接乘以当前实时的输入信号绝对强度（$X_{norm}$），瞬间算出一张反映“当前需求”的动态热力图。
这等同于提取了模型自身的物理特征作为路由（Router），在每一次吐出新词时，都从头独立评估所有的全连接层，并**物理切断排名垫底的 70% 的无用连接**。由于它是基于当前绝对值进行局部点积（$Z_t \approx X_t \cdot W_{masked}$），彻底斩断了时序上的误差累加，从而成功用 30% 的激活率实现了极其流畅的语言生成。

> **⚠️ 工程提示**：本仓库目前的 Python 代码通过掩码（Mask）相乘的方式完成了这一算法在数学层面的完美验证。要在端侧设备上真正兑现这 70% 的计算量与发热节省，未来需要基于此逻辑编写定制的底层硬件算子（如 Metal / CUDA Kernel），使其在寻址前就直接跳过这 70% 闲置区块的计算。

### 3. 读写分离的非对称架构 (Asymmetric Prefill-Decode)
在极限测试中，通过让模型阅读完全未知的虚构知识（如科幻小说），可以观察到大模型被过度稀疏化时的“失忆症陷阱”：在阅读阶段强制休眠大量神经元，会直接摧毁模型的 In-Context Learning（上下文学习）能力。
基于这一现象，可以确立针对端侧大模型的“非对称”读写物理规律：
*   **读题（Prefill）**：必须严格保持 100% 满血计算，确保外部新知识、长逻辑被无损烙印进模型的 KV Cache 中。
*   **答题（Decode）**：全面接管，启动动态绝对稀疏，以极低的功耗和激活率完成高质量的文本生成。

## 仓库模块导引

本仓库采用高内聚、自包含的模块化设计，每个探索方向的代码与验证工具均独立存在：
*   `weight_clustering/`：包含权重特征聚类、重排图谱生成与校准数据的提取脚本。
*   `dynamic_sparsity/`：包含基于“动态绝对稀疏”与“非对称架构”的端到端推断验证代码。
*   `utils/`：包含模型权重加载、训练进度留存等底层通用基础设施。
